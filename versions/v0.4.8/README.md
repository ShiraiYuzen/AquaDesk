# AquaDesk v0.4.8

> 发布：2026-10-31 · 产物 `AquaDesk-0.4.8.exe`（69.6 MB，自包含单文件）· **当前最新**

## 一句话

设置页从「改一下存一下」改成「改完点保存」，所有多选一的选项统一成下拉框；
窗口最大化时 Dock 让开的速度从慢半拍（~600ms）压到跟手（~96ms）。
另外顺手重排了版本号：状态胶囊改网格系统那一版（原来的 0.3.12）提成了 0.4.0。

## 版本号：这一天重排了两次

| 轮次 | 做了什么 | 结果 |
| --- | --- | --- |
| 第一轮 | 下午连出十几个包，一个功能反复调就烧一个号，看不出交付了什么 | 按「一件交付 = 一个版本」压成 0.3.4 ~ 0.3.11 |
| 第二轮 | 状态胶囊从「每项自带 margin、两排各自居中」换成**固定列宽网格系统** | 从那一版起改叫 0.4.0，往后 0.4.1 ~ 0.4.8 |

为什么第二版值得抬次版本号：`0.4.0` 之后每一个排布需求——设置提到第一位、拆输入法、
上 5 下 4、按数量自动分行、电量跨格、宽度随内容自适应——都只是往这套网格里加规则，
**没有一次回头改结构**。地基换了，后面五版都是在这个地基上盖的。

原来那个 `0.3.15` 的 Release 对应现在的 **0.4.3**，内容和源码一致，只是编号变了。

## 0.4.3 之后这五版

### 后台面板会漏掉「当前正在用的那个程序」（0.4.4）

同时开着 WorkBuddy 和 WorkBuddy AI，面板里只有最小化的那个。根因不是去重——是
`Consider()` 里一句 `if (hwnd == foreground) return`，把当前前台窗口整个跳过了。
胶囊是 `WS_EX_NOACTIVATE`，点它不抢焦点，所以用户刚用完的程序一直是前台，
它就从这个列表里彻底消失。

现在前台那条照样列出，副标题写「当前前台 · 标题」、右侧提示「已在前台」，
排序是「最小化 → 前台 → 其他」。

### 设置页三个毛病（0.4.5）

- **设置窗口不出现在 Dock 的预览条里**：预览服务里 `if (processId == self) return`
  是按进程一刀切的，本意只是别让 Dock 预览自己，结果把设置窗口也一起排除了。
  改成只排除自己的浮层（`OverlayZOrder.IsOverlay`）。
- **单选行选中后文字消失**：选中态把背景刷成不透明的 `#F3F8FF`，而深色主题的前景色
  是 `#F2F5FA`——白字压白底，那一行整个看不见。
- **窗口最大化时浮层沉底**：新增 `OverlayZOrder`，前台窗口最大化或全屏时
  `Topmost = false` + `SetWindowPos(HWND_BOTTOM)`，还原后抬回最前。
  光把 `Topmost` 设成 false 不够——那只是退回普通窗口层，仍然压着已经打开的普通窗口。

### 设置页换了套框架（0.4.6 / 0.4.7）

**保存按钮**：设置项仍然实时生效（拖滑块 Dock 立刻变），但不再每次改动都写盘。
改过任何一项→底部才冒出「保存」；点一下落盘、按钮收起、淡出「已保存」；
关窗（× / Esc / 完成）时若有未保存改动会兜底存一次。

**多选一全部改成下拉框**：窗口层级、停靠位置、暂停时机，原来是四行单选占掉半屏。
下拉框整只重画——系统那套是浅色立体样式，放进深色设置页像块补丁。

顺手删掉 `RadioRow` 样式和 `AppSettings` 里八个「只为 RadioButton 双向绑定而存在」的
只读布尔（`EdgeBottom/EdgeTop/...`、`PauseNever/PauseWhen*`），现在 `Edge` / `PauseMode` /
`TopMode` 三个枚举属性就是唯一数据源。

### Dock 让开得太慢（0.4.8）

原来 z 序判断和暂停策略挤在同一个 1.2 秒的计时器里，而且优先级是 `Background`。
两个原因叠加，实测从按下最大化到 Dock 沉底中位 **~600ms**，最坏满 1.2 秒。

拆成两条轮询：

| 计时器 | 间隔 | 优先级 | 管什么 |
| --- | --- | --- | --- |
| `_zTimer` | 120ms | `Normal` | 只管 z 序 |
| `_pauseTimer` | 1200ms | `Background` | 暂停策略 |

**优先级那一半比间隔更关键**：最大化瞬间 DWM 和 WPF 正在重绘，队列里全是 `Normal` 级
渲染工作，`Background` 级的 tick 会被一直往后推——哪怕间隔改成 0，也照样要等重绘忙完。

实测中位 **96ms**（8 次采样 74~107ms），抬回 99ms。

## 升级注意

配置自动迁移，不用手工改 `%AppData%\AquaDesk\settings.json`：

- `SettingsVersion = 2`：老配置里 Dock 上的 Windows / AquaDesk 两个图标会被关掉（入口在胶囊上）
- `ShowBatteryPercent` 是新字段，默认关
- `TopMode` 是新字段，默认「最大化时让开」
- 原来每改一项就自动写盘，现在要按「保存」；关窗时会兜底保存，不会丢

## 几个值得记下来的坑

1. **`DispatcherPriority.Background` 不是「低优先级」的意思，是「队列空了才轮到我」**。
   界面正在重绘时它会被无限期推后，所有「要跟手」的轮询都不能用它。
2. **`TabControl` 模板里的按钮拿不到字段**。五个分页共用底部一条按钮栏，写在模板里，
   `x:Name` 不生成字段，代码侧只能 `RootTabs.Template.FindName(...)` 按名字取。
3. **选中态别用不透明浅底**。深色主题前景接近白色，`IsChecked` 里刷个 `#F3F8FF`
   就是白字压白底；要么用强调色半透明（`#330A84FF`），要么连前景色一起换。
4. **枚举属性比布尔代理干净**。给 RadioButton 写 `EdgeBottom/EdgeTop/EdgeLeft/EdgeRight`
   四个只读布尔轮流传 `false`，还不如 `SelectedValue` 直接绑枚举。
5. **测延迟别靠肉眼**。轮询 `WS_EX_TOPMOST` 位计时，几百毫秒的差别才有数字可比较。
